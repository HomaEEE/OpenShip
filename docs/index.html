OpenShip Deploy — Мастер настройки сервера

Единый инструмент для тюнинга Ubuntu VPS, установки стеков (FrankenPHP/Caddy, MariaDB, Redis, Docker, site-cli), развёртывания панели OpenShip и аудита безопасности (doctor.sh --audit). Настройте шаги слева — готовая команда обновится справа.

1. Интерактивный мастер install.sh
curl -fsSL https://raw.githubusercontent.com/HomaEEE/OpenShip-deploy/main/install.sh | sudo bash
Запуск на сервере с пошаговым выбором: тюнинг ОС, стеки и панель OpenShip.
2. Аудит безопасности VPS doctor.sh --audit
curl -fsSL https://raw.githubusercontent.com/HomaEEE/OpenShip-deploy/main/doctor.sh | sudo bash -s -- --audit
Проверяет SSH, UFW, открытые порты БД, Fail2ban, обновления, SUID и FrankenPHP.
3. Клонирование репозитория Git
git clone https://github.com/HomaEEE/OpenShip-deploy.git && cd OpenShip-deploy
Локальная проверка скриптов перед запуском (sudo ./install.sh --help).
⚡ Быстрые пресеты
⚙️

Шаг 1. Режим и роль сервера

Выберите, будет ли этот VPS панелью управления OpenShip или worker-сервером для проектов.

Host Control Terminal --no-host-control Если выключено, Control VPS изолирован и Docker Engine в Bare+Caddy не устанавливается (экономия ~200 MB RAM).
📦

Шаг 2. Программные стеки

Опциональная установка веб-сервера, БД и утилит сразу после системного тюнинга.

Для worker-сервера под PHP/Laravel/WordPress выбирайте Full FrankenPHP Stack, под контейнеры — Docker.
FrankenPHP (Caddy + PHP) --with-frankenphp Один бинарник с авто-SSL (Let's Encrypt), HTTP/3 и встроенным PHP без php-fpm.
MariaDB Server & Client --with-mariadb Локальная БД на 127.0.0.1:3306 (не торчит наружу).
Redis Cache --with-redis Кэш и очереди на 127.0.0.1:6379.
Docker Engine & Compose v2 --with-docker Официальный Docker CE и плагин Compose v2.
site-cli --with-site-cli Утилита /usr/local/bin/site-cli для создания сайтов в FrankenPHP/Caddy и БД.
Удалить Apache2 автоматически --purge-apache Останавливает и удаляет предустановленный Apache2, чтобы освободить :80/:443 и RAM.
⚠️ Порты :80/:443: OpenShip Proxy (Caddy/Edge) уже занимает :80/:443, поэтому FrankenPHP автоматически поднимется локально на 127.0.0.1:8080.
🌐

Шаг 3. Домен, Proxy и Администратор OpenShip

Настройка публичного доступа к панели и учётной записи администратора.

DNS A-запись должна указывать на IP этого VPS. Для локального режима оставьте пустым.
Caddy рекомендуется для Bare-режима на малых VPS.
Для проксирования через Cloudflare без петель редиректа выбирайте Flexible или Origin CA.
Минимум 8 символов; передаётся только при первом запуске панели.
🛡️

Шаг 4. Тюнинг ОС и безопасность

Параметры ядра, swap, SSH, firewall и защиты от перебора паролей.

Системное имя сервера (hostnamectl).
Часовой пояс для логов и cron (например, Europe/Kyiv).
Автоматически открывается в UFW и прописывается в Fail2ban.
Пользователь с sudo-правами для SSH-доступа.
Если указан, добавляется в authorized_keys и включает вход только по ключу.
Защищает Node.js/сборки от OOM-kill при нехватке RAM.
UFW Firewall --disable-ufw Разрешает только SSH, :80 и :443; закрывает :3001, :4000, :3306, :6379 снаружи.
Fail2ban SSH Protection --disable-fail2ban Автобан IP после серии неудачных попыток входа по SSH.
💡 Совет: После установки запустите sudo ./doctor.sh --audit (вкладка audit) для проверки SSH, firewall, портов БД и SUID-бинарников.
📚 Справочник параметров: install.sh, site-cli и doctor.sh --audit

install.sh (основные флаги)

  • --mode=bare|standard|tune-only — выбор режима
  • --tune-only — только тюнинг и стеки без OpenShip
  • --stack=frankenphp|docker|custom|none — пресет стека
  • --with-frankenphp / --with-mariadb / --with-redis / --with-docker / --with-site-cli
  • --no-host-control — изоляция Control VPS (без Docker в Bare+Caddy)
  • --purge-apache — автоудаление Apache2

site-cli (FrankenPHP / Caddy)

  • site-cli create site.com --template=laravel --ssl
  • --template= opencart, wordpress, laravel, php, static, proxy
  • site-cli list — список сайтов в /etc/frankenphp/sites.d
  • site-cli ssl site.com — включение авто-TLS
  • site-cli db site.com [create|dump|drop]
  • site-cli delete site.com --with-db

doctor.sh --audit

  • PermitRootLogin, PasswordAuthentication, порт SSH
  • UFW/nftables и открытые порты БД (3306/5432/6379/27017)
  • Fail2ban sshd jail и совпадение порта с sshd -T
  • Неудачные входы за 24ч и security-обновления apt
  • Аккаунты с UID 0, sudo-логирование, политика паролей, SUID
  • --report /path/report.txt — экспорт отчёта
